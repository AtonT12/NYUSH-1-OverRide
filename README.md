# NYUSH-1 — VEX U Override Small Robot

VEX V5 competition program in C++11, built with the VEXcode makefile.
13 motors: 8-motor Omni X-drive, fine and coarse lift, claw, toggle.

## Build

VEX SDK `V5_20240802_15_00_00`, program slot 3.

```bash
VEX="$HOME/AppData/Roaming/Code/User/globalStorage/vexrobotics.vexcode"
TOOL="$VEX/tools/cpp/toolchain_win32"
PATH="$TOOL/gcc/bin:$TOOL/tools/bin:$TOOL/clang/bin:$PATH" \
  make T="$VEX/sdk/cpp/V5/V5_20240802_15_00_00" P=NYUSH-1
```

Or use **Build** in the VEX extension. Output is `build/NYUSH-1.bin`.

## Host tests

```bash
bash tests/run_tests.sh
```

Needs only `g++`; no VEX SDK, no robot. Covers the mixer, input shaping, the
replay timebase, the recorded-program encoding and the recorder's frame
selection.

## Module responsibilities

| Module | Responsibility |
| --- | --- |
| `control/command` | The single normalized command type; teleop, playback and the recorder all speak it |
| `control/shaping` | Radial deadband with rescaling, scalar and vector slew; a rate of 0 leaves a channel unshaped |
| `control/kinematics` | X-drive mixing and a proportional clamp, so saturation slows the robot instead of bending its direction |
| `control/timebase` | Absolute tick grid: waits until the next tick rather than for a fixed period, so the loop cannot drift |
| `control/auton` | 12-byte frame encoding, CRC-32 file header, in-place frame writer, time-indexed sampling with interpolation |
| `robot-config` | Brain, Controller and all 13 motor bindings; direction normalization; readiness; stopping modes |
| `motor-control` | RPM limiting, signed spin and null-safe stop |
| `drivetrain` | Four wheel groups, mixing plus clamping, encoder reset |
| `command-apply` | One dispatcher for teleop and playback, so the two cannot drift apart mechanism by mechanism |
| `recorder` | Encodes shaped commands in place in an 18 KB buffer and writes `auton.bin` |
| `auton-runner` | Replays a stored program on the tick grid with a 30 s budget |
| `mechanism` | One or two motors driven as a single axis; stops with the configured hold mode |
| `coarse-lift` | Port 5 travel limit: tracks the bottom of travel and caps the top 202° above it |

`robot-config` depends on nothing but the SDK. The control core depends on
nothing but the C++ standard library. `main.cpp` is the only module that wires
input, control core and hardware together; there are no cyclic includes.

## Run modes

Set `RobotConstants::kBootRunMode` in `include/constants.h`.

| Mode | Behaviour |
| --- | --- |
| `Locked` | motors stopped, stick values on screen |
| `Bench` | drivetrain capped to 60 rpm |
| `Field` | full competition output (boot default) |
| `Record` | `Field`, plus writing `auton.bin` to the SD card |

## Driver controls

| Input | Action |
| --- | --- |
| Left stick Axis3 / Axis4 | forward / strafe |
| Right stick Axis1 | turn |
| Axis2 | coarse lift (port 5) |
| L1 / L2 | fine lift up / down (ports 9, 10) |
| R1 / R2 | claw close / open |
| A or X | toggle |
| **Y + Down** held at boot | play the stored autonomous routine |

Translation has no deadband; turn and coarse lift use 0.2. Translation and turn
ramp at 4/s and 2/s; the coarse lift is unshaped.

## Competition behaviour

### Pre-autonomous

- Stops every bound motor.
- Zeroes all eight drive motor encoders after confirming the drivetrain is fully
  bound. This is a position reset only and assumes the robot is at rest.
- Shows project, hardware-binding and autonomous status on the Brain screen.
- **Y + Down** held at power-on plays the stored routine once, then returns.
- No IMU, gyro or other sensor calibration is performed, because no such sensor
  is part of the current hardware specification.

### Autonomous

- Stops every bound motor on entry.
- Runs `AutonPrograms::kSelected` through `AutonRunner`; an empty table prints
  `NO AUTON` and returns immediately.
- Samples on the ideal grid at the program's period, so a late loop cannot
  stretch the routine; frames missed while the CPU was busy are skipped rather
  than replayed back to back.
- Stops at the end of the table or at the 30 s period budget, whichever comes
  first, so a routine cannot overrun into driver control.
- Replays recorded wheel and mechanism commands; it is open loop and does not
  correct for being placed differently on the field.
- Stops every bound motor on exit.

### Driver control

- Stops every bound motor on entry.
- Each 20 ms tick: read the sticks and buttons, build one `UserCommand`, apply
  deadband and slew, hand it to `CommandApply`, and record it in `Record` mode.
- `dt` comes from the schedule, not the wall clock, so a stalled loop produces
  one larger slew step instead of a jump.
- Displays the three drive axes and whether output is live, every 10 ticks.
- On exit: stop every motor, then write `auton.bin` if the run was recorded.

### Stopping behaviour

- Drive motors use `brake`; mechanism motors use `hold` at full torque.
- Leaving driver control, or any readiness failure, stops the affected motors
  rather than leaving them at their last command.
- An unplugged motor marks its subsystem not ready and refuses to move.

## Motor bindings

| Port(s) | Device |
| --- | --- |
| 1, 2 | Drive front-left (6:1, both reversed) |
| 4, 14 | Drive front-right (6:1) |
| 7, 8 | Drive rear-left (6:1, both reversed) |
| 3, 19 | Drive rear-right (6:1) |
| 9, 10 | Fine lift (36:1, port 10 reversed) |
| 5 | Coarse lift (36:1) |
| 6 | Claw (18:1) |
| 13 | Toggle (18:1) |

Positive wheel RPM means forward for every group. Direction sign-off:
`docs/hardware.md`.

## Autonomous

1. Set `kBootRunMode = RunMode::Record`, build, download.
2. Drive one run. `auton.bin` is written to the SD card on disable.
3. `python tools/ovr_encode.py auton.bin` rewrites `src/auton/programs.cpp`.
4. Set `kBootRunMode = RunMode::Field`, build, download.

Format and limits: `docs/auton.md`.
